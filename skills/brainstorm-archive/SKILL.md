# 推演归档：编号文档体系

把一轮讨论落成 docs 里的一个推演文件夹。已验证范例：`star-site-docs/项目管理/头脑风暴/2026-10-12-竞品对标与单域定位推演/`（01~07 七件套）。

## 位置与命名

- 目录：`star-site-docs/项目管理/头脑风暴/<YYYY-MM-DD>-<主题>/`
- 文件：`NN-中文名.md`，NN 为两位编号，文件名与编号语义对应（见下）。

## 编号语义（按需裁剪，顺序不变）

| 编号 | 语义 | 说明 |
|---|---|---|
| 01 | 现状/竞品对标 | 事实层：对手是谁、强弱在哪、能学什么 |
| 02 | 核心推演 | 论证层：命题、机制、反方、结论先行 |
| 03 | 结论与行动清单 | 决策层：A/S 系列编号、优先级、与既有文档的关系 |
| 04+ | 按主题的专项 | 信任/安全/技术方案等，编号顺延 |
| 05+ | 方法论/双主线 | 学习策略、协作原则等横向内容 |
| 最后一份 | **主线/执行层** | 一句话 + 一个环 + 带钟里程碑 + 不做清单 + 死亡判定 |

## 每份文档的硬格式

1. 头部引用块：`> 日期 / > 议题 / > 结论先行`（结论先行是铁律，读者只看头部也能拿到结论）。
2. 结论用表格收口，论证用完整句子，不用箭头链和黑话。
3. 诚实标注**前提分支**（结论在什么条件下不成立）与**死亡判定**（提前写好怎么算失败）。
4. 行动项统一编号（A=产品动作、S=安全动作、E=体验动作…），供里程碑引用。

## 交叉引用纪律

- 03（行动清单）必须回挂所有来源文档，并在"与既有文档的关系"里写明对既有清单（如 MLP 行动清单）的修正。
- 最后的主线文档开头声明：**与其他文档冲突时以本文为准**（论证层 vs 执行层）。
- 每份新文档产出后，把它挂进主线文档的"与既有文档的关系"一节，保持引用闭环。

## 产出流程

1. 先探底再动笔：读 docs 既有相关文档，编号接着排，不另起炉灶。
2. 每份文档写完即落盘（Write 工具），全部完成后 `ls` 验证真实存在。
3. 落盘后在会话里给用户：文档链接 + 三句话摘要 + "代码一行没动"的边界声明（若适用）。
