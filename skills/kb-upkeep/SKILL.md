# 知识库维护闭环（体检 → 修复 → 增补）

目标库默认 `/Users/yangzhini/Documents/GitHub/MUYI`（可用参数换库）。一切动作遵循库规约：`====/----` 分层标题、无外链图片（示意用 ASCII/表格）、文末来源标注、一篇一 commit。

## 第一步：体检（audit）

跑本目录 `scripts/audit.sh [库路径]`，产出六类报告（stdout）：

1. **空壳文档**：0 字节或有效行 <8 的 md（排除 picture/readme 占位）
2. **链接占位**：有效行 ≤8 且含 http 链接的 md（排除已知链接集合页：推荐阅读/瞎看系列/大模型学习材料/front_Q_address）
3. **外链图片测活**（抽样或全量 `-f`）：`![](https://...)` 逐 URL 探测，分类 OK/DEAD(404)/ERR(网络不可判)
4. **库内相对死链**：md 里的相对链接解析后文件不存在（目录重组后必查项）
5. **文字外链测活**（抽样 20 或全量 `-l`）：md 正文文字链接逐条探测（先剥离图片链避免与 3 重复；仅 http/https，请求前校验 host 拒绝内网/环回地址）。404/410 记 DEAD；403/反爬记 warn 人工复核；000 记 unknown 分轮复测。防的是"文件挪了子目录、仓库改名/合并后，README 与正文里的老链接悄悄失效"（实例：MUYI 文章挪进 `分布式ID/` 子目录后主页链接缺路径段；guo-skills 并入 constellation 后 MUYI README 仍指旧仓）
6. **结构统计**：各轨 md 计数、总数，与 README 声称数比对

体检结论给用户一页纸：每类问题数量 + 清单 + 建议动作。

## 第二步：修复（fix）

按体检报告逐类修，**每类一个 commit**：

**链接占位回填**（处理顺序严格三级）：
1. **库内同源**：旧链接若指向 github.com/DemoTransfer/*（用户旧仓库已合并），内容多半就在本库其它目录——grep 文件名/主题找原文，整理互链，标注 `> 内容来源：本库 [相对路径]（原外链已失效）· 整理日期。`
2. **外链抓取**：WebFetch（被微信验证页拦时换 web_reader MCP）抓原文，忠实整理（保留原意、可精炼 80-180 行、图表转 ASCII），标注 `> 内容来源：[原文](链接) · 整理日期。` 注意考证：掘金旧域 juejin.im 已 301 迁 juejin.cn、被删文章找 SegmentFault/腾讯云镜像
3. **按题重写**：确证失效（404/作者删除/反爬）后按文件名题目自写（参考同目录风格），标注 `> 原链接已失效，重写日期 依据主题重写。`

**外链死图本地化**（上游同名匹配法）：
1. `git clone --depth 1` 上游图源仓（MUYI 对应 `https://github.com/DemoTransfer/JavaGuide`）到 /tmp
2. 对每个 DEAD url：URL 解码取 basename → 上游 find 同名（大小写不敏感）→ 命中 cp 到 `<库>/images/legacy/`，md 引用替换为 `/images/legacy/<名>`（GitHub md 支持仓库根相对路径）
3. 匹配不到的：引用行替换为 `*（alt 或"原示意图" · 原图源已失效）*`
4. 网络不可判的（ERR）当轮不动，留待下个网络窗口复测（github.com 间歇阻断是常态，测活脚本要容忍并分轮跑）

**相对死链**：能对上现有文件的批量改路径（python 全库替换，替换后再跑一次死链检查归零）；对不上的（目标文件真不存在）改指最接近的现存篇或删除链接保留文字。

**文字外链死链**（按 DEAD 清单逐条修）：
1. 文件移动致路径缺段 → `find` 定位现路径，补全子目录段（实例：`分布式系统/分布式ID-…` → `分布式系统/分布式ID/分布式ID-…`）
2. 仓库改名/合并 → 改指新仓（实例：guo-skills → constellation）
3. 纯装饰性且长期不可达的第三方徽章/挂件（如国内网络连不通的 vercel）→ 直接删除，数字信息用文字补
4. 修完全量 `-l` 复测归零；unknown 项（000）留待下个网络窗口复测，不当轮强修

## 第三步：增补（grow）

依据 `<库>/C-架构与云原生/方法论/知识库优化计划.md` 的优先级（P0 面试必考缺口 > P1 时效升级 > P3 AI 栈），每主题一篇：
- 写作前先读 1-2 篇同目录现有文对齐风格
- 结构：原理（ASCII 图）+ 代码/配置片段 + 对比表 + 追问链（`> **面试官：**`）+「面试官视角小结」
- 生产反哺类必须引用真实类名/文件路径
- 完成后更新《自测清单.md》对应题的 🕳 → 实链，README 计数同步

## 验收标准（每轮收尾必查）

1. `audit.sh` 重跑：空壳 0、链接占位 0、相对死链 0、文字外链死链 0（warn/unknown 项记录在案不强清）
2. 来源标注覆盖所有回填篇；新篇带日期标记
3. README 计数 = 实际 md 数；git log 符合"一篇一 commit 或一类一 commit"
